# 模型请求提示词 Hook

本页描述 2026-11-21 开发中的请求扩展。公开安装包、版本和源码身份以 README 顶部下载区为准。

## 在 APP 中使用

1. 打开 LLM 服务商，进入模型列表并编辑目标模型。
2. 打开该模型的请求 Hook，选择 System、User 或双通道。
3. 填写补充指令，或套用原创研究模板后编辑；保存后在新的模型运行中使用。
4. 在提示词工坊的请求快照中核对通道、配置短哈希和估计开销；按实际回复和工具结果评估任务表现。

设置独立保存在模型配置内。切换模型会切换相应策略，远端目录刷新保留本地策略。默认关闭，正文上限 16,000 字符。借用小布的文本通道只支持 User；HTTP 模型可选择三种通道。

编辑中的提示词、通道、开关、上下文和思考档位保存在本地界面恢复状态中，重建后仍可继续编辑；只有点保存才写入模型配置。恢复时校验服务商和模型条目，取消或保存后再次打开其他模型会重新读取该条目的设置。

## 注入方式

| 通道 | 最终逻辑请求中的位置 | 用途 |
| --- | --- | --- |
| System | 原有前导 system/developer 指令之后的独立 system 消息，由协议构造器合并到对应系统指令字段 | 保留独立系统指令通道的服务 |
| User | 最后一条真实用户消息正文之前；多模态消息增加独立 text block | 需要将补充指令随用户内容发送的服务 |
| 双通道 | 同时使用以上两处 | 明确需要在两处发送同一份指令的配置；上下文开销计算两份 |

四种 HTTP 协议分别转换到 Chat Completions 的 system/messages、Responses 的 instructions/input、Anthropic Messages 的 system/messages、Gemini Interactions 的 system_instruction/input。用户选择启用 Hook 时，消息相关字段在额外请求体合并后继续以运行时投影为准。

投影从 ProviderRequest 的原始消息生成请求副本，单个请求缓存一次；技术错误重试复用该副本，后续工具轮从未注入的原始消息重新投影。没有按正文子串判断“已经注入”的哨兵，因此用户引用同一段文字不会意外关闭配置。图片块、工具调用 ID、thinking/原生签名和工具结果保持原状；临时观察、上下文摘要和角色卡合成的深度提示不充当 User 通道的插入目标。小布文本选择与 Anthropic 当前工具轮的边界同样识别这些合成消息，出站时剥离内部标记。

注入文本不写回聊天数据库，不成为新的用户消息，也不进入上下文压缩后的持久历史。历史裁剪预留其估计 token 开销；预留超过历史份额时，继续按完整轮次裁到最小保留量，而不会跳过裁剪。实际请求用量沿用服务商回执；已知窗口连 Hook 本身都容纳不下时在发送前报告配置错误。

## 作用范围

- 普通聊天与工具续轮使用本次模型配置。
- 子代理跟随主模型时继承对应配置；指定独立模型时使用该模型自己的策略。授权按服务商和本地模型条目保存；同名 API 模型使用不同选择键，服务商排序不会改变授权。旧的唯一 API 名仍兼容；旧名称存在歧义时需在子智能体设置中重新选择具体条目。
- 多模型对比按各模型独立应用，保持原有无工具执行模式。
- 摘要、语音转写修正、角色回复改写与自动复盘保留专用请求配置。
- 原有工具开关、能力检查、取消与技术错误重试继续在原路径执行。

## 可观察结果

请求快照记录 Hook 的启用状态、通道、内容版本短哈希与估计 token。合成 Hook 的正文省略，User 正文继续只统计长度；复制与导出不包含省略的 Hook 正文。快照记录的是请求组装配置，真实 HTTP 请求由协议回归另行验证。

模型返回正文、调用工具或受到服务端过滤是不同结果。应用不会以关键词未命中、状态条变色或 HTTP 200 直接判定任务完成。

## 项目研究如何转化为实现

| 一手项目 | 观察到的机制 | ETA 的实现选择 |
| --- | --- | --- |
| [Fujiang 0.4.3](https://github.com/c3cvld7aag/fujiang-dsh/blob/ab86ddcd169f0f13bc74923b6ed95eda55224931/index.js) | 注册两段 system prompt | 提供独立可选 System 通道，配置按模型保存 |
| [Fujiang 0.7.0 源码](https://github.com/enticingns/fujiang-armor/blob/20674abcb6b6bf938a3cce62f4e82462b6ad3a86/index.js) | 请求前改写最后 user、保留图片，以正文前缀去重 | 采用保留多模态的 User 通道；用请求生命周期管理重复调用，不采用子串哨兵 |
| [Purge continue/retry](https://github.com/kingcharleslzy-ai/dsh-purge/blob/e519253d5b01344056055af9d2041dcafa42fed3/lib/continue-retry.js) | 请求错误重试与 idle 续行分开，依据错误码、取消与预算 | 复用 ETA 现有有界技术错误重试和取消控制；策略配置不更改原有任务结束语义 |
| [Purge refusal retry](https://github.com/kingcharleslzy-ai/dsh-purge/blob/e519253d5b01344056055af9d2041dcafa42fed3/lib/refusal-retry.js) | 流开头缓冲、正则判定与多次请求改写，保留上轮输出作失败回退 | 本轮不采用关键词评分充当任务验收；真实请求结构与结果分别检查 |
| [Purge host core](https://github.com/kingcharleslzy-ai/dsh-purge/blob/e519253d5b01344056055af9d2041dcafa42fed3/lib/core.js) | 宿主路径定位、备份、profile/shim 和包内补丁编排，补丁表另在 patches 下 | ETA 直接使用自身请求入口，未移植 DSH 宿主补丁 |

以上是请求上下文或宿主实现。调研没有把插件加载回执当作模型权重变化，也没有量化宣称所有模型的任务提升。酷安原帖与仓库作者的身份链目前仍缺可核验来源，未归名到某个仓库。本轮代码和研究模板独立实现，没有复制第三方角色正文。

## 验证

测试覆盖以下层次：

- 持久化与运行配置：模型存储、旧版本迁移、备份、远端刷新、子模型、跨进程传递和专用用途隔离。
- 请求投影：原始历史不变、多模态与工具原生状态保留、真实用户定位、预算、正文碰撞及重试稳定。
- 最终 HTTP 协议：本机 loopback 服务捕获四种真实 provider 的 POST 正文，用明确标记验证通道、次数、图片和工具链；测试同时区分 HTTP 错误和成功返回。
- 跨进程长文本：通用用例验证真实只读描述符的延迟物化与完整内容；独立 POSIX 集成用例验证创建、unlink 后继续读取及清理。Windows 宿主明确跳过后者，Linux 发布门禁要求它实际通过，平台跳过不记为已执行。
- 子模型授权：保存的授权经数据库重开，走真实 SubagentExecutor 到运行配置边界；校验同名模型的 Hook、工具清单中的唯一选择键、失效授权和未知模型均不静默回落。
- 编辑恢复：真实 Compose Composition 和 SaveableStateRegistry 执行保存、销毁、恢复，核对当前标签、编辑身份、启用/禁用草稿、通道、文本及取消/保存后重开隔离；另用纯 Saver 验证 16,001 字符的待纠正文本完整保留。

- 完整本地回归 2,517 项测试，0 失败、0 错误、71 项宿主平台跳过（2,446 项实际通过）；Lint 与 Debug 构建通过。源码指纹 `88c31047…00152` 在构建前、构建后与本轮封存证据完全一致。
- 强制功能门禁 47 个必过套件、72 个关键场景无跳过通过；技能恢复 8 例、显式子模型停用竞态、Compose 编辑恢复 3 例均实际执行通过。
- 原证书签名的 ARM64 非调试 Release 预览 `3.5.6.15+model-hook` 已通过签名、包身份、R8、天气保留、已退休功能缺失和 Hook 打包内容核验，大小 11,287,124 字节，SHA-256 `ad21b4e5a4cb5a6030c2899611259df167d45a6bd253e710ab5232b5162ec598`。
- 本轮封存证据包含 400 份 JUnit、逐源文件哈希与不可变归档，可执行 `.eta-tools/model-prompt-evidence-20261122/seal.ps1 -Mode verify` 只读复核。
- 真机/OEM ROM、完整 Activity 生命周期、Linux 专属 POSIX 未链接描述符写入及远端模型开关对照仍未验证。
