# 功能精简与天气保留 — 2026-11-21

本轮按明确指令移除五组功能。该阶段完成回归和 GitHub 正式发布后，才开展后续 Agent 项目调研；本页不把尚未实现的插件或能力描述为已有功能。

## 天气完整保留

- 天气预报、当前位置／行政区解析、常用地点、天气设置、缓存、过期状态、刷新和失败时保留缓存的行为保留。
- 桌面天气组件及其十条原文案保留，原先与通知栏指令共用的文案已逐字移入独立资源。
- WeatherWidgetSettingsActivity 仅承载原天气设置页，使用原外观主题；组件点击改为这个独立入口，不再经过已退休的磁贴配置页。
- 天气服务、定位／常用地点偏好、天气解析和缓存算法未为本次精简重写。
- 普通文字和链接分享直接进入聊天草稿，不自动发送；图片和文件的原附件流程保留。

长期记忆、复盘审批、普通附件和文件检索、会话模型对比及采样、非 NFC 定时／事件任务、星驰四种手动兼容预设也保留。普通设备状态工具中的 NFC 开关与 NFC 任务触发属于不同能力，不为移除任务而删掉其他设备控制。

## 升级与旧备份

不需要修改 Room 表结构或逻辑备份 JSON schema。本轮新增 DAO 查询而非数据库重建，聊天、模型、记忆和普通任务的表不清空。

1. 调度刷新和入队前，在同一 Room transaction 中精确读取并移除 triggerJson.type 为 nfc_tapped 的旧任务及其运行记录，避免扫描后并发改成普通规则时被误删。
2. 父任务即使早已改成 daily／interval，也分别清理其活动运行中 eventJson.type 为 nfc_tapped 或规范 fireKey 前缀为 nfc_tapped: 的旧项；不根据标题、提示词或正文子串判断。普通队列和已完成历史保留。
3. 只有在无其他活动运行、且 queued 摘要／冷却时间确实由被移除项写入时，才恢复上一条普通运行摘要；不扣运行次数、不误停用普通任务。启动和开机先清理，再做 interrupted 恢复；Job dispatch 进入模型前再次检查旧 NFC 项。
4. 全量备份的导出、ZIP 解压暂存及应用旧暂存三条路径均排除 files/knowledge-library 和旧 eta_daily_notes／eta_quick_tiles 偏好（含 .bak）。逻辑导入继续忽略未知旧字段。
5. 不批量释放 SAF 持久 URI 授权：普通附件与旧文档库可能共享同一个 UID／URI 授权。不删除外部原文，也不操作普通附件、聊天或天气设置。

导出回归还暴露了既有 ZIP 内部缓冲未刷新导致尾部不完整的问题：导出现在完成 ZIP 后刷新自己包装的缓冲，但不关闭调用者流；刷新失败向调用者报告失败，取消和原始错误不被收尾错误替换。

私有文件还原先把输入以有界内存缓冲暂存到应用缓存 ZIP，使用 `ZipFile` 验证中央目录，并逐个校验待还原条目的长度与 CRC。条目边界截断、解压失败或取消时清理 incoming，保留原完整 pending；只在全部成功后重命名发布，previous 目录支持发布中断恢复，成功应用后不会再复活旧目录。临时压缩包需要相应缓存空间，并在退出时清理。UI 中逻辑 JSON 导入与私有文件暂存仍是分开的阶段；私有暂存失败时，先前已完成的逻辑导入保持已提交状态。

退休备忘句式仅作为负向路由判断保留，统一处理礼貌前缀。普通入口、等待天气地点的追问和导航保护均不会把这些正文当作地点，正常北京／杭州查询继续工作。
