# 天气定位与电源键助理：工单评审与综合方案（2026-11-18）

本文是对外部工单《方案-Eta语音持久化与天气修复工单-20261118》的核对结果、修正意见，以及本仓库实际落地的综合工单。结论均来自源码阅读、公开接口实测与本地回归，不包含未验证的推断。

## 一、对原工单的判断

### 成立且已采纳

| 原工单结论 | 核对情况 | 本仓库处置 |
| --- | --- | --- |
| Open-Meteo geocoding 对中国县级以下地名无收录 | 与实测一致：`大余县`、`池江镇` 返回空结果 | 增加 OpenStreetMap 地名源作为区县/乡镇补充，预报仍只用坐标 |
| 客户端 2s/3s/4s 超时过苛 | 与源码一致（旧配置 connect 2s、read 3s、call 4s，且不重试） | 改为 connect 8s、read 10s、call 15s，并对明确可重试的网络错误做一次退避重试 |
| 自动定位只读系统缓存，从不主动请求 | 与源码一致（`DeviceLocationProvider.latest` 只调用 `getLastKnownLocation`） | 新增有界主动定位，20 秒超时，所有退出路径都取消请求并释放监听 |
| 403 与真正的网络故障混为一谈 | 与源码一致（任何异常都落到同一句“地点搜索失败”） | 按 HTTP 状态与异常类型分类，给出可区分文案 |

### 不采纳或需要修正

1. **不建议把 Nominatim 作为首选地名源。** 其公开使用政策明确要求：绝对上限每秒 1 次请求、必须提供可识别的 User-Agent、禁止客户端自动补全、必须缓存结果、并允许随时切换服务。原工单给出的实现没有防抖、没有缓存、也没有切换机制，按此上线会影响对方服务，也不满足其政策。本仓库改为使用支持结构化结果与自动补全语义更明确的 Photon 公开实例，并且只在用户显式点击搜索时发起请求，客户端侧串行 + 1.2 秒最小间隔 + 结果缓存 + 限流退避。
2. **不建议用「取第一个存在的 event 节点」作兜底。** 原工单自己已经证明按键设备枚举顺序会随重启变化；再保留任意 event 兜底，等于把故障随机化。设备选择必须以该节点是否真的上报电源键能力为准，找不到就明确失败并报诊断，而不是猜一个。
3. **不建议在开机广播里直接批量改系统设置。** 原工单示例同时写入 `assistant`、`voice_interaction_service`、`appops 119`、`appops 10020`、覆盖 `enabled_accessibility_services` 并 `pm disable-user` 厂商助手。其中 appops 编号跨 Android 版本不稳定，覆盖无障碍服务列表会清掉用户的其他服务，禁用厂商助手属于用户选择。本仓库不这样做：默认助理的绑定与校正由 system_server 侧在开机完成阶段与用户解锁时按已保存选择重放，且只动 Eta 自己的条目。
4. **不建议把「退出码 0」当成真机已验证。** `cmd voiceinteraction show` 返回成功只说明请求被受理，不代表胶囊真的显示。原工单在此处的结论需要真机确认，本仓库文档中也不宣称已验证。

### 原工单未覆盖、但同样会导致「长按电源键没反应」的一点

HyperOS 的快捷动作分发路径在会话启动失败时没有后台修复，而 ColorOS 路径有。重启后 `secure assistant` / `voice_interaction_service` 可能尚未落盘，第一次长按就会失败且此后不再重试。本仓库补齐了这条：HyperOS 分支在启动失败时入队一次有界后台配置修复（每 20 秒最多一次），本次仍不启动任何 Activity、不改变前台应用。

## 二、本次综合工单（已落地）

### A. 天气：能定位到当前位置，也能查区县乡镇

1. **按需主动定位**：新增单次定位请求，20 秒上限，同时请求融合/网络/GPS 中可用的提供者，取精度最好的一份；结束时取消所有请求。绝不把几小时前的历史位置当作当前位置。
2. **地点搜索分层**：区县/乡镇这类细粒度查询先走向 OpenStreetMap 数据源，市级及更粗的查询先走 Open-Meteo；两者都失败才算失败，任一源返回空但另一源有结果时以有结果者为准。
3. **严格行政区校验**：给出「省 + 市 + 县 + 镇」时，结果必须同时命中叶子名称与各级父级，避免把同名乡镇错配到别的省。数据源省略地级市时，只在省级与县级都明确命中时接受该缺项。
4. **不伪造精度**：预报只使用坐标，地点名称仅用于展示；找不到乡镇就明确说找不到，不用上级行政中心顶替。
5. **手动坐标入口**：天气设置页可直接输入纬度/经度保存为地点，绕开所有地名库盲区。
6. **错误分类**：区分超时、DNS、TLS、连接失败、限流（带重试秒数）、访问被拒、响应格式异常，文案各不相同。
7. **设置页与聊天共用同一份常用地点**：旧版两套存储已合并，升级时自动迁移，避免「设置里选了地点、聊天里却还在用旧的」。
8. **刷新按钮真的刷新**：原先只更新时间戳；现在先取当前位置再请求预报，失败时给出具体原因。

### B. 助理：重启后长按电源键仍能唤起

1. **HyperOS 失败自愈**：见上文，启动失败时入队一次后台默认助理修复。
2. **保留既有能力**：ColorOS 的 `OplusSpeechHandler` 拦截、开机完成阶段与用户解锁时的配置重放、启动失败后的有界重试链均保持原样。
3. **不越权**：不改用户其他无障碍服务，不禁用任何厂商助手，不写跨版本不稳定的 appops 编号。

### C. 仍需要真机验证的部分（如实标注）

- 长按电源键在重启后能否一次成功，取决于目标机型 system_server 的实际类名与字段是否与本仓库 hook 目标匹配。仓库侧只保证「失败后会自愈」，不宣称在所有 HyperOS 版本上都命中。
- 手机上的外置 root 守护脚本不在本仓库内，其设备选择逻辑需要在该脚本自身维护；本仓库不打包、也不模拟那套脚本。
- 室内 GNSS 冷启动仍可能超时，此时应提示到窗边/户外重试或选择常用地点，而不是显示「联网失败」。
