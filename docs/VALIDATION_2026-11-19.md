## 本轮发现并修正的旧问题

- 后台复盘使用已被清理的 run → 会话映射，生成空归属卡；显示和按钮归属不一致，使跳过失效。
- 用户消息复制与编辑、删除共用运行态禁用开关。
- `JSONArray.put(index, value)` 被误当成插入，采样 instruct 会替换掉一条历史或当前用户消息。
- 磁贴执行结果仅 Toast 后立刻还原；UAPI 缓存互斥锁覆盖了网络等待。
- KB / 屏幕定位只有声明、NFC 只有 Receiver、模型对比与采样面板没有完整生产入口。
- 结构化历史按字符取尾会得到损坏 JSON；按空历史恢复会掩盖损坏。journal 的存储别名还可能随 history 压缩改变。
- 通用分块写入擅自裁掉超过阈值的字段；升级启动自动维护也会裁原文，现改为只体检。手动瘦身明确说明会永久裁掉较早原文；“继续”被裸词媒体快捷路由抢走。
- 首次内置提供商缺少模型播种，目录迁移和用户连接顺序存在遗漏。
- 首次工作区不存在、裁切预览接受视图外起点，以及数据层拒权检查等边界问题。

## 发布硬门禁

发布流水线同时依赖完整验证和签名 Release 构建。`scripts/verify_feature_test_reports.py` 检查关键测试类与指定原生集成方法确实执行通过；缺失、失败或跳过均使该门禁失败，不能依赖未命中的 `--tests` 过滤器返回成功。

签名正式包由提交后的干净 `main` 构建，启用 R8 与资源裁剪，检查应用 ID、非 debuggable、仅 ARM64、APK 签名与升级证书。公开资产的版本、提交和 SHA256 以发布时生成的 `release-info.json` 为准；源码推送成功不等于正式版已发布。

## 能力边界

KB 是 UTF-8 文本关键词检索；屏幕定位依据已有 UI 节点，不是 OCR / OmniParser。NFC 需要前台主动读卡。天气组件默认只读缓存，显式刷新沿用位置权限与地点配置。对比结果会增加所选供应商的请求费用，工具执行在对比中关闭。真机麦克风、厂商唤醒、QS 渲染、NFC 硬件及桌面组件行为仍需对应设备验证。
